# DocSearch — вопросы к своим документам, полностью офлайн

Настольное приложение для macOS: загружаете договоры, регламенты, судебные материалы (PDF, Word, Excel, PowerPoint…), задаёте вопрос обычным языком и получаете точный ответ **со ссылками на фрагменты документов**, из которых он взят.

- **Работает без интернета.** Нейросеть, база и документы лежат на вашем компьютере, наружу ничего не уходит. Это подходит для объектов КИИ и для коммерческих заказчиков, которым нельзя отдавать документы в облако.
- **Отвечает только по документам.** Если ответа в документах нет, приложение так и пишет, а не выдумывает.
- **Отдельное окно, без браузера и без Docker.** Для серверной установки есть вариант в контейнерах ([ниже](#вариант-для-сервера-docker)).

```
Вопрос: «В каком суде рассматриваются споры по договору?»
Ответ:  Споры рассматриваются в Арбитражном суде г. Москвы [2].
        [2] Договор_подряда_15.pdf, стр. 7
```

## Установка на MacBook

> 📘 **Подробная пошаговая инструкция с типичными ошибками и решениями: [INSTALL.md](INSTALL.md)**

Коротко. Нужен macOS 11+ и интернет только на время установки (около 3–6 ГБ). Откройте **Терминал** и выполните:

```bash
git clone https://github.com/ilugly/docpoisk.git ~/docpoisk
cd ~/docpoisk && bash install.sh
```

**Уже ставили раньше?** `git clone` повторять не нужно. Обновление для любой версии, включая первую:

```bash
cd ~/docpoisk && git fetch origin && git reset --hard origin/main && bash install.sh
```

Документы, база и настройки при обновлении сохраняются.

Скрипт сам:
- поставит Python 3.12 и библиотеки в отдельную папку `.venv`, не трогая систему;
- установит [Ollama](https://ollama.com), программу, которая запускает нейросети локально и использует видеоядро Apple Silicon;
- подберёт модель под объём памяти: 8 ГБ → `qwen2.5:3b`, 16 ГБ → `qwen2.5:7b`, 24+ ГБ → `qwen2.5:14b`;
- скачает модели и создаст приложение **DocSearch** в `~/Applications`. Его можно найти через Spotlight или Launchpad.

Дальше приложение запускается как обычное, интернет больше не нужен.

> Если окно не открывается, запустите `bash run.sh --browser`: интерфейс откроется в браузере, а всё остальное будет работать так же, локально.

## Как пользоваться

Тема оформления (светлая, тёмная или как в системе) переключается кнопкой в правом верхнем углу.

1. **Загрузите документы.** Перетащите файлы в левую панель. Под каждым файлом виден прогресс: «читаю текст → считаю эмбеддинги → готово».
2. **Задайте вопрос** в строке внизу. Ответ печатается по мере генерации, номера `[1]`, `[2]` в тексте кликабельны и показывают исходный фрагмент.
3. **Поиск по конкретным документам.** Отметьте их галочками, и поиск пойдёт только по ним. Это полезно, когда загружено много похожих договоров.
4. **База знаний.** На вкладке «База знаний» видны все загруженные документы: название, формат, размер, число страниц и фрагментов, дата загрузки. Документы можно искать по названию, фильтровать по формату и сортировать. По клику открывается карточка документа: его разделы и весь распознанный текст с поиском по нему. Оттуда же документ можно открыть, скачать, переиндексировать, удалить или задать вопросы только по нему.
5. **Связи между документами.** Для каждого документа определяются тип (договор, доп. соглашение, письмо, претензия, акт…), номер, дата и стороны. Доп. соглашения, письма и акты, где упоминается «Договор № 15 от 01.02.2024», привязываются к этому договору сами. Цепочки видны в «База знаний» → «Связи». Ошибочную связь можно убрать, а недостающую добавить вручную в карточке документа.
6. **Сводная редакция договора.** В карточке договора (или доп. соглашения) есть кнопка «Сводная редакция». Приложение применяет к договору все привязанные доп. соглашения по порядку дат. Распознаются правки вида «пункт 2.1 изложить в следующей редакции», «дополнить пунктом 3.2», «пункт 5.2 исключить», «в пункте 2.2 слова «…» заменить словами «…»», «раздел 7 изложить…». Результат можно:
   - посмотреть с выделенными правками и основанием каждой («ДС № 1 от 10.03.2024, п. 3»);
   - скачать в Word, чистовым или с выделением правок;
   - добавить в базу знаний, чтобы задавать вопросы по действующей редакции;
   - попросить нейросеть объяснить, что изменилось и кому это выгодно.

   Тексты пунктов переносятся правилами дословно, без нейросети, поэтому суммы и сроки не искажаются. Нейросеть подключается только для нестандартных формулировок, и такие правки помечаются «сверьте». То, что разобрать не удалось, приложение показывает прямо, а не пропускает молча.
7. **Сравнение документов.** В карточке: «Сравнить с…». Пункты сопоставляются по номерам, различия подсвечиваются пословно.
8. **Риски.** В карточке: «Анализ рисков». Можно выбрать, за какую сторону вы играете. Анализ идёт в два слоя:
   - правила находят типовые риски: высокую и неограниченную неустойку, односторонний отказ или изменение условий, молчаливую приёмку, длинные сроки оплаты, аванс без обеспечения, асимметричную ответственность, отсутствие форс-мажора и подсудности;
   - нейросеть критически читает каждый пункт и добавляет то, что правилами не поймать. Её риски без реального номера пункта отбрасываются.

   В письмах ищутся претензии, требования со сроками, признание долга, уведомления о расторжении. Если письмо ссылается на «п. 5.1», рядом показывается текст этого пункта из связанного договора. Все результаты собираются во вкладке «Реестр рисков» и выгружаются в Excel.
9. **Много файлов сразу:** положите их в папку `~/DocPoisk/inbox` и нажмите «из папки inbox».

Поддерживаемые форматы: **PDF, DOCX, XLSX, PPTX, ODT, RTF, TXT, MD, CSV, JSON, HTML, XML**.
Старые `.doc/.xls/.ppt` пересохраните в новый формат через Word/Pages. Сканы без текстового слоя сначала прогоните через OCR, например ABBYY FineReader или «Экспорт в PDF» с распознаванием.

Все данные хранятся в `~/DocPoisk`:

| Что | Где |
|---|---|
| Настройки (модель, размер чанков) | `~/DocPoisk/settings.env` |
| Векторная база | `~/DocPoisk/vectordb` |
| Копии загруженных файлов | `~/DocPoisk/files` |
| Лог (если что-то пошло не так) | `~/DocPoisk/app.log`, `~/DocPoisk/logs/` |
| Пользователи (хеши паролей) и журнал входов | `~/DocPoisk/auth` |
| Реквизиты, ручные связи, сводные редакции, реестры рисков | `~/DocPoisk/files` |

Папка данных по-прежнему называется `~/DocPoisk` (старое имя приложения), чтобы при обновлении ничего не потерялось.

## Вход, пользователи и администрирование

**Вход по паролю.** При первом запуске приложение просит создать администратора. Дальше без входа нельзя ни открыть документы, ни задать вопрос. Это касается и всех запросов к серверу, не только интерфейса.
- Пароли хранятся только в виде хеша (scrypt с солью).
- Сессия хранится в защищённой cookie и действует 12 часов (настройка `SESSION_HOURS`).
- После 5 неверных паролей вход для этого имени блокируется на 5 минут.
- Смена пароля или блокировка пользователя сразу завершает все его сессии.
- Форма входа обычная, поэтому браузер и менеджеры паролей (Связка ключей iCloud, 1Password и т. п.) предлагают сохранить и подставить пароль, если открыть приложение в браузере (`bash run.sh --browser` или Docker-вариант).

**Роли.** *Пользователь* работает с документами, вопросами, анализом и рисками. *Администратору* дополнительно доступен раздел **«Админ»**:
- **Пользователи** — добавить, сменить роль, сбросить пароль, заблокировать, удалить. Последнего администратора удалить или понизить нельзя.
- **Журнал** — кто, когда и с какого адреса входил, а также неудачные попытки входа. Там же главные действия: загрузка, скачивание и удаление документов, вопросы, анализ рисков, выгрузки, изменения пользователей, команды консоли. Есть фильтр по пользователю и действию.
- **Логи** — логи сервисов с просмотром последних строк. «Скачать все логи (zip)» выгружает логи, журнал и список пользователей (без паролей).
- **Консоль** — команды, которые напрямую исправляют данные приложения. Например:

  | Команда | Что делает |
  |---|---|
  | `docs` | список документов с id |
  | `meta 1a2b set type=amendment number=2 date=15.04.2024` | исправить неверно определённые тип, номер или дату документа |
  | `link 1a2b 9f8e` / `unlink …` | привязать письмо или ДС к договору / убрать связь |
  | `risks 9f8e`, затем `risk 9f8e 3 del` или `risk 9f8e 2 set level=низкий` | убрать ложный риск или поправить уровень |
  | `risk 9f8e add clause=4.2 level=высокий risk="Нет гарантии качества"` | добавить риск вручную |
  | `clauses 9f8e` | как приложение разобрало пункты договора |
  | `search срок оплаты` | что находит поиск (проверка качества) |
  | `cons 9f8e` | пересобрать сводную редакцию |
  | `reindex outdated`, `delete …`, `jobs`, `stats`, `audit 50`, `config` | обслуживание |

  `help` выводит полный список. Можно написать и обычным языком, например «поменяй тип письма 45 на претензию». Нейросеть предложит команду, но выполнится она только после нажатия кнопки. Исправления записываются в журнал.

- **Сервисы** — из каких частей состоит программа и работает ли каждая: интерфейс, сервис документов и анализа (`ingest`), сервис вопросов (`chat`), векторная база (`qdrant`), нейросети (`ollama`). В настольной версии все они работают внутри одного приложения. В Docker-версии у каждого свой контейнер (см. «Версия для разработчика»).

**Консоль в Терминале** — те же команды без окна приложения:
```bash
cd ~/docpoisk && bash run.sh --console
```
Если приложение открыто, консоль подключается к нему и просит войти администратором. Если закрыто, работает с данными напрямую, без входа.

**Забыли пароль администратора.** Закройте приложение, выполните `bash run.sh --console` и введите `passwd <имя> <новый пароль>`.

## Как это устроено (RAG)

```
            ИНДЕКСАЦИЯ (один раз на документ)
 Файл ──► извлечение текста ──► нарезка на чанки ──► эмбеддинги ──► векторная база
 PDF/DOCX/…   (parsing.py)      ~1000 символов,      (bge-m3,        (Qdrant,
                                перекрытие 200       вектор 1024)     косинусная близость)
                                (chunking.py)

            ВОПРОС
 Вопрос ──► уточнение по диалогу ──► векторный поиск ─┐
            («а там?» → «какая        (bge-m3)        ├─► объединение ──► + соседние ──► LLM ──► ответ
             неустойка по              поиск по словам ┘    (RRF)          фрагменты      (qwen2.5)  + ссылки
             договору № 15?»)          (BM25)
```

1. **Извлечение текста.** Для каждого формата своя библиотека: `pypdf`, `python-docx` (с таблицами), `openpyxl` и т.д. Номера страниц сохраняются, чтобы потом сослаться на них.
2. **Чанки.** Текст режется на куски примерно по 1000 символов, по возможности по границам абзацев и предложений, с перекрытием, чтобы пункт договора не разрывался пополам.
3. **Эмбеддинги.** Модель `bge-m3` превращает каждый чанк в вектор из 1024 чисел. Похожие по смыслу тексты получают близкие векторы, даже если слова в них разные: «подсудность» найдётся по вопросу «в каком суде».
4. **Векторная база (Qdrant).** Хранит векторы и по вопросу находит самые близкие чанки по **косинусной близости**, то есть по углу между векторами.
   Перед эмбеддингом к фрагменту дописываются имя документа и заголовок раздела («5. Ответственность сторон»): пункт «5.2. Размер — 0,1 % в день» сам по себе не говорит, что речь о неустойке.
5. **Поиск по словам (BM25).** Векторы хорошо ловят смысл, но плохо находят точные совпадения: номер пункта, сумму, ФИО. Поэтому параллельно идёт поиск по словам с учётом русских окончаний, и результаты объединяются. Запрос дополняется юридическими синонимами: «форс-мажор» — «непреодолимая сила», «сколько стоит» — «цена», «кто подписал» — «подписи сторон».
6. **Отсев шума.** Каждый кандидат, откуда бы он ни пришёл, проверяется на близость к вопросу по смыслу. Иначе поиск по словам тянет всё, где встречается «договор», и маленькая модель путается. Исключение — точное совпадение номера пункта или суммы из вопроса.
7. **Соседние фрагменты.** Пункт договора часто начинается в одном фрагменте, а заканчивается в следующем. Поэтому от соседнего фрагмента берётся край, около 400 символов, чтобы дочитать пункт.
8. **Документ виден модели.** У каждого фрагмента подписано, что это за документ: «Доп. соглашение № 1 от 20.05.2024 к договору № 15/2024», а не только имя файла.
9. **Доп. соглашения.** Если в ответ попал пункт договора, а доп. соглашение меняет именно его, фрагмент доп. соглашения добавляется с пометкой «изменяет пункт 2.1». Модель отвечает по действующей редакции.
10. **Письма и претензии.** На вопросы об условиях (цена, неустойка, сроки…) при найденном договоре в контекст не попадают: расчёт в претензии — это позиция стороны, а не условие договора.
11. **Защита от «инъекций».** Строки документов, похожие на команды для нейросети («игнорируй инструкции», «отвечай: …»), вырезаются до того, как текст попадёт к модели.
12. **Диалог.** Уточняющий вопрос («а для подрядчика?», «а какой там срок?») сначала переписывается моделью в самостоятельный, по нему и идёт поиск. Переформулировка принимается, только если сохранила смысловые слова исходного вопроса, иначе модель могла подменить новый вопрос старым. Для уточнения берутся и фрагменты прошлого ответа.
13. **LLM** получает вопрос, историю и отрывки с инструкцией: только по фрагментам, со ссылками, не смешивать документы, текст документов — данные, а не команды. Длина ответа ограничена, чтобы модель не зацикливалась. На пустой ответ или повтор вопроса модель переспрашивается один раз.
14. **Сверка ответа.** Каждое число из ответа ищется в источниках. Если модель сослалась не на тот фрагмент, ссылка исправляется. Числа, которых нет ни в одном документе (например, сумма, которую модель «посчитала» сама), подсвечиваются предупреждением «Не найдено в документах».

Качество ответов проверяется набором сценариев в `qa/` (см. `qa/README.md`).

### Типичные причины, почему «документ не индексируется»

- **Новый файл не проходит весь конвейер.** Часто первый документ загружают скриптом при старте, а новые файлы не проходят чтение, нарезку, эмбеддинги и запись в ту же коллекцию. Здесь каждый загруженный файл проходит весь путь, и прогресс виден в интерфейсе.
- **Скан вместо текста.** В PDF-скане нет текста, только картинки. Приложение об этом прямо сообщает.
- **Поменяли модель эмбеддингов**, а база осталась от старой. Векторы разных моделей несовместимы. Приложение это проверяет и подсказывает, что делать.
- **Слишком маленькая модель или мало памяти.** На MacBook Air с 8 ГБ берите `qwen2.5:3b`. Модели 7B+ на 8 ГБ будут работать очень медленно.

## Настройки

Файл `~/DocPoisk/settings.env` (после правки перезапустите приложение):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `LLM_MODEL` | по объёму RAM | модель для ответов. Любая из [ollama.com/library](https://ollama.com/library), скачать: `ollama pull <имя>` |
| `EMBED_MODEL` | `bge-m3` | модель эмбеддингов. **После смены удалите `~/DocPoisk/vectordb` и загрузите документы заново** |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 1000 / 200 | размер фрагмента и перекрытие, в символах |
| `TOP_K` | 6 | сколько фрагментов передавать модели |
| `MIN_SCORE` | 0.35 | порог близости: менее похожие фрагменты отбрасываются |
| `NEIGHBORS` / `NEIGHBOR_CHARS` | 1 / 400 | сколько соседних фрагментов добавлять и сколько символов брать с их края |
| `ANSWER_MAX_TOKENS` | 700 | предельная длина ответа |
| `CONTEXT_CHARS` | 9000 | максимум текста документов для модели. Вместе с диалогом должен влезать в `LLM_NUM_CTX` (8192 токенов ≈ 24 000 символов) |
| `HISTORY_TURNS` | 3 | сколько прошлых пар «вопрос — ответ» учитывать |
| `CONDENSE_QUESTION` | 1 | переписывать уточняющие вопросы с учётом диалога. `0` — быстрее, но уточнения понимаются хуже |

**После обновления приложения** над списком документов появится ссылка «Обновить индекс старых документов». Нажмите её один раз: документы переиндексируются с заголовками разделов и реквизитами (тип, номер, дата), и модель начнёт понимать, какой документ перед ней и что меняют доп. соглашения. Старые документы работают и без этого, но хуже.

## Вариант для сервера (Docker)

Те же модули, разнесённые по контейнерам: `web` (nginx), `ingest` (индексация), `chat` (ответы), `qdrant` (векторная БД), `ollama` (нейросети). Подходит для Linux-сервера в закрытом контуре, к которому подключаются несколько сотрудников.

```bash
cp .env.example .env
docker compose up -d --build
docker compose logs -f models     # дождаться «Все модели готовы»
```

Интерфейс откроется на http://localhost:8080. На Mac Docker не даёт доступа к видеоядру, поэтому нейросеть в контейнере работает в несколько раз медленнее, чем в настольном приложении.

**Перенос на компьютер без интернета:** на машине с интернетом выполните `docker compose pull && docker compose build` и дождитесь моделей. Затем `docker save` образов плюс папка `data/ollama` переносятся на целевую машину.

## Версия для разработчика (Docker, всё по контейнерам)

Настольное приложение (`install.sh`, `~/Applications/DocSearch.app`) контейнеров не использует: все части работают внутри него, и Docker не нужен. Версия с контейнерами запускается отдельно, из той же папки, и нужна для разработки или сервера.

**Что нужно:** установленный и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/), 8+ ГБ свободной памяти и интернет при первом запуске (скачиваются образы и модели, около 6 ГБ). Контейнеры появятся в Docker Desktop в группе `docpoisk` после команды `bash dev.sh up`. Документы и пользователи у Docker-версии свои, в папке `~/docpoisk/data`, отдельно от настольного приложения.

**Ollama.** Если на компьютере уже работает Ollama (её ставит `install.sh` для настольного приложения), `dev.sh up` не поднимает свою Ollama в контейнере, а подключает контейнеры к ней. Так быстрее: в контейнере на Mac нет доступа к видеоядру, а модели уже скачаны. Чтобы всё-таки запустить Ollama в контейнере: `OLLAMA_IN_DOCKER=1 bash dev.sh up` (порт 11435).

**Занятые порты.** Перед запуском `dev.sh` проверяет порты и подсказывает, если какой-то занят. Сменить порт можно так: `WEB_PORT=8090 bash dev.sh up`. Остальные: `DEV_INGEST_PORT`, `DEV_CHAT_PORT`, `DEV_QDRANT_PORT`, `DEV_OLLAMA_PORT`.

Каждый сервис работает в своём контейнере:

| Контейнер | Что делает | Порт для разработчика |
|---|---|---|
| `web` | интерфейс (nginx) | http://localhost:8080 |
| `ingest` | вход и пользователи, загрузка и индексация, анализ, администрирование | http://127.0.0.1:8001/docs |
| `chat` | вопросы и ответы | http://127.0.0.1:8002/docs |
| `qdrant` | векторная база | http://127.0.0.1:6333/dashboard |
| `ollama` | нейросети (или Ollama на самом компьютере) | http://127.0.0.1:11435 (в контейнере) |

Отличия от обычного Docker-варианта: код подключён с диска и перезапускается при сохранении, логи подробные (`DEBUG`), порты сервисов открыты (только для этого компьютера).

```bash
bash dev.sh up             # собрать и запустить
bash dev.sh logs ingest    # логи сервиса в реальном времени (ingest, chat, web, qdrant, ollama)
bash dev.sh export-logs    # все логи контейнеров + журнал входов → data/exports/logs_<дата>.tar.gz
bash dev.sh admin-console  # консоль администратора в терминале
bash dev.sh test           # тесты внутри контейнера
bash dev.sh down           # остановить
```

Где лежат данные:
- логи приложения: `data/logs/<сервис>.log`, с ротацией;
- журнал входов и действий: `data/auth/audit.jsonl`, по строке JSON на событие;
- пользователи: `data/auth/users.json`, только хеши паролей.
